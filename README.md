# stuffRegistry

Учебный HTTP-сервис на Go для кадрового учёта сотрудников. Через API можно добавить сотрудника, получить список сотрудников и удалить запись по ID. У каждого сотрудника есть ФИО и должность, а уникальный ID назначает PostgreSQL.

Проект объединяет работу с HTTP, SQL и Docker: приложение и база данных запускаются в отдельных контейнерах, структура базы создаётся миграциями, а команды запуска собраны в Makefile.

## Технологии

- Go 1.27 и стандартный пакет `net/http` — HTTP-сервер.
- Gorilla Mux — маршрутизация запросов.
- PostgreSQL 18 и `pgx/v5` — хранение данных и подключение к БД.
- `golang-migrate` — SQL-миграции.
- Docker, Docker Compose и Make — сборка и запуск проекта.

## Запуск через Docker

Нужны работающий Docker с Docker Compose и установленный `make`. Go и `migrate` на компьютере для этого способа запуска не требуются. Порты `8090` и `5432` должны быть свободны.

### 1. Склонировать репозиторий

```bash
git clone https://github.com/l0gik67/stuffRegistry.git
cd stuffRegistry
```

### 2. Создать `.env`

В корне проекта создай файл `.env`. Пример значений для локальной разработки:

```dotenv
DATABASE_HOST=localhost
DATABASE_PORT=5432
DATABASE_USER=app
DATABASE_PASSWORD=dev_password
DATABASE_NAME=stuff_registry
DATABASE_URL=postgres://${DATABASE_USER}:${DATABASE_PASSWORD}@${DATABASE_HOST}:${DATABASE_PORT}/${DATABASE_NAME}?sslmode=disable
```

`.env` не хранится в Git и не копируется в Docker-образ. Compose передаёт настройки приложению при запуске контейнера.

Для запуска Go на компьютере используется адрес `localhost:5432`. В контейнере приложения Compose переопределяет `DATABASE_URL`, указывая адрес `postgres:5432`: `postgres` — имя сервиса базы данных в общей Docker-сети.

### 3. Запустить сервис

```bash
make run-http-app
```

Команда последовательно:

1. Запускает PostgreSQL и ожидает, пока база начнёт принимать подключения.
2. Применяет новые миграции через отдельный контейнер `migrate`.
3. Собирает образ приложения и запускает его в фоне с публикацией порта `8090`.

При повторном запуске уже применённые миграции повторно не выполняются. Контейнер миграций удаляется после завершения команды.

Используй `make run-http-app` для полного запуска: ожидание готовности базы и применение миграций описаны в Makefile. Обычный `docker compose up` не выполняет эту последовательность.

### 4. Проверить доступность

```bash
curl -i http://localhost:8090/employees
```

Если база пока пустая, ответ будет `200 OK` с телом `[]`.

Посмотреть контейнеры и логи:

```bash
docker compose ps
docker compose logs -f application postgres
```

Остановить проект:

```bash
make service_undeploy
```

Данные PostgreSQL сохраняются в именованном volume `postgres_data` и остаются после этой команды. При следующем запуске сервис использует ту же базу.

## HTTP API

Базовый адрес: `http://localhost:8090`.

| Метод | Маршрут | Действие | Успешный ответ |
| --- | --- | --- | --- |
| `POST` | `/employees` | Создать сотрудника | `201 Created`, созданный сотрудник |
| `GET` | `/employees` | Получить список сотрудников | `200 OK`, массив сотрудников |
| `DELETE` | `/employees/{id}` | Удалить сотрудника по ID | `200 OK`, удалённый сотрудник |

Успешные ответы возвращаются в JSON. Ошибки возвращаются обычным текстом.

### Создать сотрудника

```bash
curl -i -X POST http://localhost:8090/employees \
  -H 'Content-Type: application/json' \
  -d '{"full_name":"Иванов Иван Иванович","position":"Go-разработчик"}'
```

Пример тела ответа:

```json
{
  "id": 1,
  "full_name": "Иванов Иван Иванович",
  "position": "Go-разработчик"
}
```

`full_name` и `position` обязательны: каждое поле должно содержать не только пробелы и быть не длиннее 255 символов. Тело запроса должно содержать один JSON-объект.

### Получить сотрудников

```bash
curl -i http://localhost:8090/employees
```

Ответ — массив объектов сотрудников. При отсутствии записей возвращается `[]`.

### Удалить сотрудника

Подставь ID из ответа на создание или из списка сотрудников:

```bash
curl -i -X DELETE http://localhost:8090/employees/1
```

При успехе сервер возвращает удалённого сотрудника. Повторное удаление того же ID вернёт `404 Not Found`.

### Ошибки

| Статус | Причина |
| --- | --- |
| `400 Bad Request` | Некорректный JSON, лишнее содержимое после JSON, неверные поля или ID вне диапазона `1..2147483647` |
| `404 Not Found` | Сотрудник с указанным ID не найден при удалении |
| `500 Internal Server Error` | Ошибка обращения к базе данных |

## Команды Makefile

| Команда | Назначение |
| --- | --- |
| `make run-http-app` | Запустить БД, применить миграции, собрать и запустить приложение |
| `make postgres-up` | Запустить только PostgreSQL и дождаться его готовности |
| `make migrate_up` | Запустить БД при необходимости и применить новые миграции |
| `make migrate_down` | Откатить все миграции; текущая down-миграция удаляет таблицу сотрудников вместе с данными |
| `make service_run` | Запустить Go-приложение локально через `go run main.go` |
| `make service_deploy` | Выполнить то же, что `make run-http-app` |
| `make service_undeploy` | Остановить и удалить контейнеры Compose, сохранив volume с данными |

## Локальный запуск приложения

Можно оставить PostgreSQL в Docker, а Go-приложение запускать на компьютере. Для этого дополнительно нужен Go 1.27 в `PATH` и `.env` из примера выше.

Если приложение уже работает в контейнере, сначала освободи порт `8090`:

```bash
docker compose stop application
```

Затем запусти базу, примени миграции и запусти Go-приложение:

```bash
make migrate_up
make service_run
```

Makefile читает `.env` и экспортирует переменные для `go run main.go`. При прямом запуске через `go run main.go` переменная `DATABASE_URL` должна уже быть задана в окружении: приложение само `.env` не читает.

## Подключение к PostgreSQL

Для подключения через pgAdmin или другой SQL-клиент используй:

- Хост: `localhost`.
- Порт: `5432`.
- Базу данных, пользователя и пароль: значения `DATABASE_NAME`, `DATABASE_USER` и `DATABASE_PASSWORD` из `.env`.

Эти настройки создают базу и пользователя при первой инициализации пустого volume. Изменение `.env` само по себе не меняет пользователя и пароль в уже существующей базе.

## Структура проекта

```text
.
├── main.go                  # Запуск HTTP-сервера на порту 8090
├── dto/
│   └── employeesDto.go      # Данные запроса на создание сотрудника
├── httpRouting/
│   └── empRouter.go         # Маршруты, обработчики и валидация запросов
├── postgres/
│   └── empService.go        # Подключение к PostgreSQL и SQL-запросы
├── migrations/             # Создание и удаление таблицы employees
├── Dockerfile              # Сборка образа Go-приложения
├── docker-compose.yaml     # Приложение, PostgreSQL и контейнер миграций
├── .dockerignore           # Исключения из контекста сборки
└── Makefile                # Команды запуска и управления миграциями
```
